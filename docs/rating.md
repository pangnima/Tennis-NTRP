# 개인 레이팅 · 티어 명세

> 현행 명세다. 상수·공식의 정본은 코드(`src/lib/rating/` + vitest)이고, 이 문서는 그 코드가 왜 그렇게 생겼는지를 적는다.
> 옛 클럽 레이팅(클럽마다 따로 굴리던 ELO, 0018)은 `docs/history/rating-system.md`에 보관본으로 있다 — 0097에서 테이블째 지웠다.

## 1. 공식 — NTRP 스케일 ELO

USTA 동적 NTRP·UTR처럼 **레이팅을 연속값으로 두고 표시만 계급으로 묶는다**(§2). ELO 기대승률을 NTRP 스케일에 직접 적용한다.

### 1.1 상수 (`lib/rating/constants.ts`)
| 상수 | 값 | 뜻 |
|---|---|---|
| `D` | 1.0 | 스케일 계수 — NTRP 1.0 차이 = 승산 10배 |
| `K_PROVISIONAL` | 0.10 | 잠정기(게임 수 < 임계) 최대 변동폭 |
| `K_BASE` | 0.05 | 정착 후 최대 변동폭 |
| `PROVISIONAL_THRESHOLD` | 10 | 잠정기 경계(게임 수) |
| `MARGIN_WEIGHT` | 0.5 | 마진 가중치(계수 1.0~1.5) |
| `DEFAULT_RATING` | 2.5 | 아무 값도 없을 때의 출발값 |
| `MIN_RATING` / `MAX_RATING` | 1.0 / 7.0 | 경계 |

### 1.2 기대 승률
```
E_A = 1 / (1 + 10^((R_B − R_A) / D))
```
NTRP 1.0 차이 → 강자 ≈ 0.909, 0.5 차이 → ≈ 0.760, 동급 → 0.500.

### 1.3 변동량
```
delta = K × marginFactor × (S − E)      S = 승 1 · 패 0 · 무 0.5
```
`(S − E)`가 "의외성"을 맡는다 — 강자가 예상대로 이기면 거의 오르지 않고, 약자가 이기면 크게 오른다.

### 1.4 K 계수
본인 게임 수가 `PROVISIONAL_THRESHOLD` 미만이면 `K_PROVISIONAL`, 이상이면 `K_BASE`. 자가선언 출발값을 실제 실력으로 빨리 옮기기 위해서다.

### 1.5 마진 계수
한 게임의 스코어(6:4처럼 하나 — 한 게임 = 스코어 하나)에서:
```
dominance    = clamp((Gw − Gl) / (Gw + Gl), 0, 1)
marginFactor = 1 + MARGIN_WEIGHT × dominance      // [1.0, 1.5]
```
6:0 → 1.5, 7:6 → 거의 1.0, 무승부 → 1.0.

### 1.6 경계
변동 뒤 `[MIN_RATING, MAX_RATING]`으로 자른다.

### 1.7 예시
- 이변승: 나 2.5 vs 상대 4.0, 6:4 승 → `E ≈ 0.031`, `mf = 1.10`, `K = 0.05` → **+0.053**
- 강자의 예상 압승: 나 4.0 vs 2.5, 6:1 승 → `E ≈ 0.969`, `mf ≈ 1.36` → **+0.002**
- 잠정기: 나 2.5(게임 0, K 0.10) vs 2.5, 6:1 승 → `mf ≈ 1.36` → **+0.068**

## 2. 티어 — 계급 + 포인트 (`lib/rating/tier.ts`)

저장은 연속 레이팅 그대로, **표시만 0.5 폭의 계급**으로 묶는다. 티어는 레이팅을 묶은 이름이라 NTRP와 같은 숫자 축이다.

| 계급 | 구간 |
|---|---|
| 아이언 | 1.00 ≤ r < 1.50 |
| 브론즈 | 1.50 ≤ r < 2.00 |
| 실버 | 2.00 ≤ r < 2.50 |
| 골드 | 2.50 ≤ r < 3.00 (기본값 2.5 = 골드 0p) |
| 플래티넘 | 3.00 ≤ r < 3.50 |
| 다이아몬드 | 3.50 ≤ r < 4.00 |
| 마스터 | 4.00 ≤ r < 4.50 |
| 챌린저 | r ≥ 4.50 (종착) |

경계는 `TIER_BANDS` 한 곳. 포인트는 저장하지 않고 레이팅에서 만든다(떨어지면 자동 강등):
```
points(r) = clamp(round((r − low) / (high − low) × 100), 0, 99)
```
보이는 곳: 프로필 헤더·티어 진행 바, 참가자 표의 NTRP 칸 옆, 랭킹. 개인 레이팅이 없거나 **통계 비공개면 그리지 않는다**.

## 3. 개인 레이팅 — 무엇을 재생하나 (`lib/rating/personal-rating.ts`)

### 3.1 입력과 계산
- 입력은 **내가 뛴 게임 중 스코어가 들어간 것**(예정 게임 제외)을 내 관점으로 바꾼 것(`toPersonalMatch` → `explodePersonalMatchSets`). 매칭 게임·직접 기록이 똑같이 들어간다.
- 매번 처음부터 다시 재생한다(`replayPersonalRatings`) — 결정적이라 같은 입력이면 같은 값이다. 통계·홈은 그 자리에서 계산한다.
- **'나' 한 명만** 추적한다. 상대·파트너의 레이팅은 굴리지 않고 그 게임에 적힌 값을 쓴다(§3.2).

### 3.2 상대 · 파트너 강도
게임에는 선수마다 **기록 시점의 NTRP 스냅샷**(`game_players.ntrp`)이 있다 — 회원이면 그때의 레이팅 캐시(`personal_ntrp`, 없으면 자가선언 — `insert_game_players`), 비회원이면 넣을 때 적은 값.

**상대(팀)** (`resolveOpponentRating`): ① 스냅샷(복식은 상대 둘 평균) → ② 상대 회원의 자가선언 `users.ntrp` → ③ 내 자가선언(동급 가정) → ④ `DEFAULT_RATING`.

**내 팀**(복식, `resolveSelfSideRating`): `avg(내 현재 레이팅, 파트너 강도)`, 파트너 강도 = ① 스냅샷 → ② 파트너 회원 `users.ntrp` → ③ 내 레이팅(무영향). 변동은 팀이 아니라 **내 레이팅에만** 적용한다.

> 비회원 상대도 적은 NTRP로 레이팅에 반영된다. 비회원 NTRP를 높게 적으면 이겼을 때 더 오르는 구조는 그대로 두었다(0107 — `docs/history/week-72-rebuild.md`).

### 3.3 시작값 · 순서 · 잠정기
- 시작 레이팅 = 본인 자가선언 `users.ntrp`(없으면 2.5).
- 순서 = `(played_at, played_time, created_at, id)` 오름차순. 한 번에 저장한 여러 게임은 `created_at`(0106의 `clock_timestamp` — 줄 순서대로 다르다)으로 입력 순서를 지킨다.
- 게임 수 < 10이면 잠정(화면에 「잠정」).

### 3.4 캐시 — `users.personal_ntrp`
- 랭킹(`get_member_rankings`)과 **다음 게임의 NTRP 스냅샷**은 매번 재생할 수 없어 캐시를 읽는다.
- 게임을 기록·수정·삭제한 액션이 **참가 회원 전원**의 캐시를 다시 계산한다(`lib/games/recompute.ts`, 소수 셋째 자리 반올림).
- 이 칸은 회원 세션으로 쓸 수 없다(0103 트리거) — `SUPABASE_SERVICE_ROLE_KEY`로만 쓴다. 키가 없으면 아무것도 갱신되지 않는다.
- 일괄 보정: `npm run db:backfill-personal-ntrp`.
